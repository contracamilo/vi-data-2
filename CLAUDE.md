## Architecture

Package in `src/hbo_max_dashboard/` with three layers; dependencies point one way (a test forbids Dash/Plotly imports in `data/` and `logic/`):
- `data/`: `repository.py` reads CSVs (only module touching disk) and returns a frozen `Catalog(titles, credits)`. `cleaning.py` parses list columns, translates genres to Spanish (`config.GENRE_LABELS`), and derives `tipo` and `decada`.
- `logic/`: `filters.Filters` (built from raw UI values via `from_inputs`) and `metrics.py`, pure functions returning DataFrames. Quality metrics only use titles with `MIN_VOTES` votes and drop small groups (`MIN_GROUP_SIZE`, `MIN_DECADE_SIZE`). Every metric must return an empty frame on an empty selection.
- `views/charts.py` is the single source of truth: each `ChartSpec(id, title, question, insight, build)` ties a question to a metric and a `figures.py` primitive. Layout, the one callback, and the notebook all iterate `CHARTS`; KPIs work the same way via `views/kpis.py` (`KPIS`). To add a chart, add a spec, nothing else.
- `figures.py` primitives receive aggregated data only and return `figures.empty()` when there is none; `ChartSpec.render` sets the title.
- The `insight` texts quote numbers computed on the full catalog. If cleaning or thresholds change, re-check them.

The `.ipynb` deliverable is generated by `tools/build_notebook.py`. It embeds every module of the package as a `%%writefile` cell (discovered automatically), followed by sections for processing, per-chart question/figure/insight, conclusions, and the inline Dash app (`jupyter_mode="inline"`). Never edit the notebook by hand.

## Reference dashboard (instructor's example)

The example was built on this same dataset (the screenshot is branded Netflix, but the data is HBO Max). Our version uses a dark purple HBO Max theme (`views/theme.py`). The slider range comes from the data (~30% of titles predate 2000). Layout, top to bottom:
- Title and subtitle.
- Filter row: Tipo (checklist: Película/Serie), Género (dropdown, "Todos los géneros"), Año de estreno (RangeSlider, 2000-2022).
- KPI row: Títulos, Películas, Series, IMDb promedio.
- Their chart grid (4 per row): titles per release year (histogram, colored by type), top genres (horizontal bar), runtime vs IMDb score (scatter), top 10 production countries (bar), top actors by number of titles (horizontal bar), age certification (donut).

The example has visible bugs to avoid: the "Títulos" KPI shows 0, and the Películas and Series KPIs show the same value (3,574). Compute each KPI from its own filtered subset.

## Data (`archive/`)

HBO Max catalog (JustWatch, US, May 2022; Kaggle) titles/credits:
- `titles.csv` (~3.3k rows): `id, title, type (MOVIE|SHOW), description, release_year, age_certification, runtime, genres, production_countries, seasons, imdb_id, imdb_score, imdb_votes, tmdb_popularity, tmdb_score`.
- `credits.csv` (~66k rows): `person_id, id, name, character, role (ACTOR|DIRECTOR)`. It joins to titles on `id`.

Gotchas for processing:
- `genres` and `production_countries` are stringified Python lists (`"['drama', 'family']"`). Parse them with `ast.literal_eval` and explode before grouping.
- `seasons` is only populated for shows, and `runtime` has a different meaning for shows (episode length), so runtime metrics use movies only.
- `credits.csv` has 74 duplicate (person_id, id, role) rows; Spearman correlation is computed via ranks because scipy is not a dependency.
- Scores, votes and `age_certification` have missing values.
